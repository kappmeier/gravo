# Gravo

Learn a language.

Vocabulary and grammar training with flashcard-style repetition for German speakers learning
English, French, Italian, Latin or Spanish. Runs on Linux and Windows.

## Projects

| Project | What it is |
|---|---|
| `GravoCore/` | VB.NET library: domain model, SQLite data access, quiz logic, settings, localization |
| `GravoCore.UnitTests/` | NUnit tests for the core |
| `GravoApp/` | C# Avalonia UI: views, view models, composition root |
| `GravoApp.Desktop/` | The desktop executable |
| `GravoApp.Tests/` | NUnit view-model tests and headless Avalonia UI tests |
| `GravoCmd/` | Command-line front end |

The vocabulary data is stored in the `voc.s3db` SQLite database as a sample. Localized texts
for the UI are stored in `languages.s3db`. The latter is copied next to the executable.

## Requirements

- .NET SDK 10.0 (defined in `global.json`)
- Windows or desktop Linux.

## Build and test

From the repository root, on either OS:

```sh
dotnet build Gravo.sln -c Release
dotnet test Gravo.sln -c Release
```

The tests can be executed also separately:

```sh
dotnet test GravoCore.UnitTests -c Release
dotnet test GravoApp.Tests -c Release
```

If no local .NET SDK is available, Docker can be used:

```sh
docker run --rm -v "$PWD":/src -w /src mcr.microsoft.com/dotnet/sdk:10.0 dotnet test Gravo.sln -c Release
```

## Run

```sh
dotnet run --project GravoApp.Desktop -c Release -- path/to/your.s3db
```

Without an argument the app tries to use a local `voc.s3db` next to the executable. Settings are
stored in `%AppData%\Gravo\settings.json` on Windows and `~/.config/Gravo/settings.json` elsewhere.

The command-line front end currently has a limited feature set and lists the groups of a database
only:

```sh
dotnet run --project GravoCmd -c Release -- voc.s3db
```

## CI/CD

On every push the solution is built and both test suites executed on `ubuntu-latest` and
`windows-latest`. Each test step enforces a minimum number of passed tests
(`TEST_FLOOR`, `UI_TEST_FLOOR` in `.github/workflows/dotnetcore.yml`). To be safe this number needs
to be adapted in the same commit that adds or removes tests. The coverage report is a workflow
artifact generated by the Linux run.

## History

Gravo started in 1995 as "Vokabeltrainer" QBasic application. It was quickly ported to Visual
Basic. Migration to Visual Basic .NET in 2003 together with the switch to a database approach in
Vokabeltrainer 2k3. Kept as a VB.NET WinForms application until 2026. The last WinForms state is
tagged `winforms-final`. The current Avalonia implementation copies exactly this status.
